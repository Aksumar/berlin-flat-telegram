# Как создаются карты объявлений

[Вернуться к основному README](../README.md#карты-и-примеры).

Координатор — [GeoapifyMaps.kt](../src/main/kotlin/com/aksumar/telegram/maps/GeoapifyMaps.kt).
Для карт нужен `GEOAPIFY_API_KEY`. Используются Geocoding, Static Maps и Places;
Routing API не вызывается. Одна готовая картинка используется для всех чатов объявления.

## 1. Найти адрес

Берётся непустой `address.full`. Если его нет, запрос собирается из улицы,
номера дома, индекса, района и города. Без ключа или адреса карта не создаётся.

Запрос в `GET https://api.geoapify.com/v1/geocode/search` использует:

| Параметр | Значение |
| --- | --- |
| `text` | Адрес |
| `format` | `json` |
| `lang` | `de` |
| `limit` | `1` |
| `filter` | `rect:13.08,52.33,13.77,52.68` |

Проверяется только первый результат; при его отклонении другие варианты не ищутся.
Результат принимается при `rank.confidence >= 0.8`, долготе `13.08–13.77`,
широте `52.33–52.68` и типе `building`, `street`, `suburb`, `district` или `postcode`.
Тип `city` отклоняется даже при высокой уверенности.
Прямоугольник задаёт область поиска вокруг Берлина, а не административную границу города.

## 2. Определить точность

Точный адрес требует одновременного выполнения трёх условий:

- `result_type=building`;
- `rank.confidence_building_level >= 0.95`;
- `rank.match_type=full_match`.

Другие принятые результаты считаются приблизительными. Пороговые значения — решения
этого приложения. При недостаточной уверенности или координатах вне области поиска
объявление отправляется без карты.

## 3. Получить подложку Geoapify

[GeoapifyStaticMaps.kt](../src/main/kotlin/com/aksumar/telegram/maps/GeoapifyStaticMaps.kt)
загружает PNG через `GET https://maps.geoapify.com/v1/staticmap`.

| Настройка | Основная карта | Обзор Берлина |
| --- | --- | --- |
| Стиль | `osm-bright` | `positron` |
| Размер | `960 × 600` | `288 × 240` |
| Масштаб | `15.5` для здания/улицы, иначе `12.5` | `11` |
| Центр | Координаты адреса | Координаты адреса |
| Метка | Красный дом для точного адреса, круг для приблизительного | Маленькая красная точка |

Карты запрашиваются без `lang`: используются местные названия, атрибуция провайдера сохраняется.
Принудительный `lang=de` в проверенных ответах Geoapify скрывал названия улиц;
геокодирование по-прежнему использует немецкий язык.
Названия улиц, их размер, цвет и размещение определяет Geoapify;
на текущем масштабе часть улиц может быть без названий.

Основная карта скрывает только `poi-level-2` и `poi-level-3`.
Слой названий районов `place-other` остаётся включённым. На крупном плане
точка подписи района может находиться за кадром, даже если квартира в этом районе.
Обзор использует масштаб `11` и более контрастные подписи `place_suburb` и `place_other`:
в проверенном кадре возле Spichernstraße Geoapify показывает Wilmersdorf, Schöneberg
и соседние районы. Названия и их размещение берутся только из подложки провайдера;
наличие подписи каждого квартала, например Bayerisches Viertel, не гарантируется.
Приоритетные объекты `poi-level-1`, железнодорожные станции и аэропорты остаются
частью изображения провайдера. Их видимость зависит от масштаба и размещения подписей.
Уровень POI обозначает приоритет, а не гарантированный размер объекта или категорию.
Железнодорожный слой содержит обычные станции тоже: стандартные значки могут
сосуществовать с карточками S/U, которые приложение рисует поверх карты.

Ошибка загрузки обзора не мешает отправить основную карту.
Точка на обзоре задаётся как `geometry=circle` радиусом 6 пикселей с центром
в координатах квартиры. Это исключает обнаруженное смещение круглого `marker`
вниз на половину его размера. Сам обзор центрирован на квартире, поэтому её
точка находится в центре обзора; положение Берлина относительно неё меняется с адресом.

## 4. Найти станции для карточек

[GeoapifyPlaces.kt](../src/main/kotlin/com/aksumar/telegram/maps/GeoapifyPlaces.kt)
запрашивает ближайшие станции метро, поездов и легкорельсового транспорта
через Places API. Для карточек выбираются U-Bahn и подтверждённые S-Bahn в видимой области.
Повторы удаляются, известные пересадки S/U объединяются в одну карточку.

Если подходящих S/U нет, отдельно запрашиваются трамвайные и автобусные остановки;
приоритет у трамвая. Транспортные запросы ограничены границами карты и двумя страницами
по 500 объектов. Объекты под обзорной вставкой не используются.
Магазины, аптеки, парки и другие нетранспортные места для собственных карточек
не запрашиваются; они могут присутствовать на самой подложке Geoapify.

## 5. Подготовить линии и разместить карточки

[VbbTransitCache.kt](../src/main/kotlin/com/aksumar/telegram/maps/VbbTransitCache.kt)
один раз при создании компонента загружает
[berlin_u_s_stations_colors.csv](../src/main/resources/berlin_u_s_stations_colors.csv).
Это справочник «нормализованное имя станции → линии S/U и HEX-цвета», без сетевых
запросов и автоматического обновления. Нормализация сопоставляет разные записи
одной станции, например `S+U Alexanderplatz Bhf` и `U Alexanderplatz`.

Для автобусов тот же компонент загружает `berlin_bus_routes.json` через
[BusRouteCatalog.kt](../src/main/kotlin/com/aksumar/telegram/maps/BusRouteCatalog.kt).
Справочник строится из GTFS VBB с учётом календаря и исключений на ближайшую неделю.
Название и координаты Geoapify сопоставляются с платформами VBB в пределах 180 м;
сокращения `Str.` и `Straße` нормализуются. Платформы общего родителя объединяются,
а без родителя объединение требует совпадения названий и близости всех платформ.
Карточка показывает маршруты обоих направлений без повторов. Неоднозначное
сопоставление оставляет название и значок B без номеров. Далёкие одноимённые
остановки не склеиваются.

Данные загружаются при запуске без сетевых запросов. После окончания периода
справочника номера сохраняются, в лог записывается предупреждение об обновлении.
Это недельный список маршрутов по расписанию, а не ближайшие отправления.
[Команда обновления, источник и лицензия](../scripts/transit/README.md).

[StationLabels.kt](../src/main/kotlin/com/aksumar/telegram/maps/StationLabels.kt)
готовит текст, строки линий и размеры карточек. Длинные названия переносятся.
Все линии S-Bahn остаются в одном ряду, все U-Bahn — в другом;
ширина карточек и столбцов легенды адаптируется к содержимому.
Автобусные номера переносятся по ширине карточки; ночные N-маршруты идут последними.
На карте с автобусными номерами добавляется указание источника «Маршруты: VBB · CC BY 4.0».
Для неизвестной станции показывается обычный значок транспорта рядом с названием.

[LandmarkRenderer.kt](../src/main/kotlin/com/aksumar/telegram/maps/LandmarkRenderer.kt)
рисует карточки с учётом размещения, рассчитанного вспомогательными классами.
Карточки избегают друг друга, метки квартиры, обзора и предупреждения о неточности.
Если места рядом нет, поиск продолжается по карте с попыткой более узкой карточки.
Оставшиеся станции переходят в нумерованную легенду под картой с соответствующими
номерами на карте. Изображение увеличивается по высоте, чтобы сохранить названия и линии.

## 6. Собрать изображение и отправить

[MapComposer.kt](../src/main/kotlin/com/aksumar/telegram/maps/MapComposer.kt)
собирает результат через Java `Graphics2D`: карта, обзор справа внизу с заголовком
«БЕРЛИН» и при необходимости предупреждение «Примерное расположение» сверху слева.
Область карты остаётся `960 × 600`; легенда добавляет высоту снизу.

Заголовок Telegram содержит источник и район, например `🏠 InBerlinWohnen · Mitte`.
Для всех источников отсутствующий или пустой район дополняется из проверенного
результата геокодирования адреса (district, затем suburb, quarter или neighbourhood).
Полученный район сохраняется и при последующей ошибке генерации карты.
Если район определить не удалось, заголовок содержит только источник,
а в лог записывается warning с идентификатором объявления и адресом.
Жилищная компания указывается отдельно, когда отличается от источника.
Кнопки «Объявление» и «📍 Карта» находятся в одной строке. Их ссылки формируются
из объявления независимо от генерации изображения. Google Maps всегда открывает
поиск по адресу объявления, без зависимости от координат и доступности Geoapify.

Картинка загружается в Telegram как файл. Ключ Geoapify не включается в ссылки сообщения.
Подпись до 1024 единиц UTF-16 отправляется вместе с фото; более длинный текст следует
отдельным тихим сообщением, сохраняя одно уведомление. Лимит текста — 4096 единиц UTF-16.
Если изображение недоступно, текст сохраняет кнопки объявления и Google Maps.
Если адрес полностью отсутствует, остаётся только кнопка объявления.
Отказ Telegram принять фото, в том числе после исчерпания повторов, приводит к попытке
отправить текст с теми же кнопками. Если и текст не доставлен после повторов при временной
ошибке, Kafka-запись сохраняется для восстановления.

## Ограничения и обработка ошибок

Запросы выполняются последовательно, без повторов Geoapify:
геокодирование, основная карта, обзор, затем транспортные места.
Таймаут соединения — 10 секунд, отдельного запроса — до 20 секунд,
общий бюджет работы с картой — 30 секунд. Каждый запрос ограничивается также остатком бюджета.

Ответ должен иметь HTTP-статус `200` и размер не более 5 000 000 байт.
Изображение должно декодироваться и иметь ожидаемые размеры.
Ошибки геокодирования или основной карты приводят к отправке объявления текстом.
В INFO-логи записываются URL запросов с параметрами без `apiKey`.
При неудачной генерации WARN содержит адрес объявления, причину, этап,
длительность и детали запроса (включая URL без ключа при ошибке HTTP).
Тела ответов и исходные сообщения исключений не записываются: они могут содержать ключ.

Документация провайдера: [Geocoding](https://apidocs.geoapify.com/docs/geocoding/forward-geocoding/),
[Static Maps](https://apidocs.geoapify.com/docs/maps/static/),
[Places](https://apidocs.geoapify.com/docs/places/).
Описание отправки фотографий: [Telegram sendPhoto](https://core.telegram.org/bots/api#sendphoto).


## Метрики Prometheus и Grafana

Приложение отдаёт метрики на `GET :8080/actuator/prometheus` через Spring Boot
Actuator и Micrometer. Порт меняется переменной `METRICS_PORT` (или `SERVER_PORT`).
Для Docker Prometheus должен видеть порт контейнера в общей сети; `EXPOSE 8080`
сам по себе не публикует порт на хосте.

Пример секции в конфигурации Prometheus (`telegram` — имя сервиса в сети Docker):

```yaml
scrape_configs:
  - job_name: berlin-flat-telegram
    scrape_interval: 15s
    metrics_path: /actuator/prometheus
    static_configs:
      - targets: ['telegram:8080']
```

В Grafana используется источник данных Prometheus. Таймеры экспортируют
`_seconds_count`, `_seconds_sum`, `_seconds_max` и `_seconds_bucket`:

| Метрика | Что измеряет |
| --- | --- |
| `telegram_maps_generation_seconds` | Полная генерация: от проверки конфигурации до готового PNG, включая неудачные попытки; без отправки в Telegram |
| `telegram_maps_request_seconds` | Каждый вызов Geoapify, включая чтение ответа и неудачные попытки |

Метка `operation`: `generation` у генерации; `geocoding`, `detail_map`,
`overview_map`, `places` у запросов. Метка `outcome`: `success`, `error`,
`http_error`, `connect_timeout`, `timeout`, `budget_exhausted`, `interrupted`.
`budget_exhausted` означает, что запрос не отправлен из-за исчерпания бюджета.
Ошибки необязательных обзора/мест учитываются в запросах, даже если генерация
в целом успешна. HTTP 200 с некорректным содержимым считается успешным HTTP-запросом;
ошибка обработки основной карты отражается в результате генерации.
Время установки соединения отдельно не измеряется: оно входит во время запроса;
его таймаут выделен как `connect_timeout`. Локальная отрисовка может закончиться
позже 30 секунд: общий бюджет ограничивает сетевые запросы, а не прерывает отрисовку.

Гистограммы имеют границы 0.1, 0.25, 0.5, 1, 2, 5, 10, 15, 20, 25, 30, 45, 60 секунд
и `+Inf`. Метки не содержат адресов, идентификаторов объявлений или API-ключей.
Серии появляются после первого соответствующего события.

Среднее время генерации (секунды):

```promql
sum(rate(telegram_maps_generation_seconds_sum[$__rate_interval]))
/
sum(rate(telegram_maps_generation_seconds_count[$__rate_interval]))
```

p95 полного времени генерации:

```promql
histogram_quantile(0.95,
  sum by (le) (rate(telegram_maps_generation_seconds_bucket[$__rate_interval]))
)
```

p95 запросов по операциям:

```promql
histogram_quantile(0.95,
  sum by (le, operation) (rate(telegram_maps_request_seconds_bucket[$__rate_interval]))
)
```

Ошибки и таймауты запросов в секунду:

```promql
sum by (operation, outcome) (
  rate(telegram_maps_request_seconds_count{outcome!="success"}[$__rate_interval])
)
```

При редких объявлениях увеличивайте интервал графика: для `rate` нужны как минимум
две точки сбора. Счётчики суммируются по экземплярам; `_max` — максимум скользящего
окна Micrometer, а не максимум за всё время работы.

Документация: [Spring Boot Prometheus endpoint](https://docs.spring.io/spring-boot/3.5/api/rest/actuator/prometheus.html).
